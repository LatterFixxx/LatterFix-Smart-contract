# feat(recovery): multi-signature admin-role social recovery protocol (#094)

Closes #94

## Summary

Adds an **emergency social-recovery** path for the contract `admin` role. Today
the admin is a single address set once in `initialize` (`src/lib.rs`) and gates
fee changes, dispute resolution, pausing, upgrades and more — if that key is
lost or compromised there is no way back. This PR lets a **threshold of top-tier
community members** (reputation tier **Master** ≥ 1000 or **Legend** ≥ 2500)
collectively rotate the admin to a new address.

It is modeled on the existing `src/multisig.rs` (snapshotted threshold,
approvals re-validated at execution, TTL expiry, atomic execution) but the
"signers" are not appointed — eligibility is earned reputation — and the only
action is the admin rotation itself.

## How it works

```text
  Pending ──(approvals ≥ threshold)──> Approved ──(execute)──> Executed
     │                                     │
     ├──────────────(cancel)───────────────┤
     │                                     │
     └────(ttl elapsed → Expired on touch)─┘
```

1. `propose_recovery(proposer, proposed_admin)` — `proposer` must be a top-tier
   guardian; their approval is recorded automatically. The live admin and the
   configured threshold are **snapshotted** into the proposal. Only one
   non-terminal proposal may exist at a time (a stale one past its TTL is lazily
   marked `Expired`).
2. `approve_recovery(guardian, recovery_id)` — each top-tier guardian adds one
   approval (`require_auth()`, host-verified). Reaching the threshold flips the
   proposal to `Approved`.
3. `execute_recovery(caller, recovery_id)` — re-counts approvals against each
   approver's **current** tier, checks the proposal hasn't expired, and verifies
   **the admin hasn't already moved since the snapshot**; then sets
   `DataKey::Admin` to the proposed address.
4. `cancel_recovery(caller, recovery_id)` — the **proposer or the sitting admin**
   can veto a `Pending`/`Approved` proposal at any time before execution.

Threshold and TTL are admin-configurable via `configure_recovery` (defaults:
**3 approvals**, **7-day TTL**).

## Acceptance criteria

| Criterion | Where |
|---|---|
| Recovery proposals | `propose_recovery` / `RecoveryProposal` |
| Collect threshold signatures from top contributors | `approve_recovery`, gated by `reputation::get_user_tier` ∈ {Master, Legend}; each approval is an on-chain `require_auth()` |
| Update admin address on validation | `execute_recovery` rotates `DataKey::Admin` |
| Recovery state machine | `RecoveryStatus { Pending, Approved, Executed, Cancelled, Expired }` with enforced transitions |
| Role transition validations | `proposed_admin != current admin`; can't approve non-`Pending` / execute non-`Approved` / act past TTL / double-execute; execution re-validates the guardian set and the `admin_at_proposal` snapshot |
| Test cases verifying successful recovery | `src/social_recovery_test.rs` — 24 tests |

## Changes

- **`src/social_recovery.rs`** — new module: types, `configure_recovery`,
  `propose_recovery`, `approve_recovery`, `execute_recovery`, `cancel_recovery`,
  `is_eligible_guardian`, `get_active_recovery`, `get_recovery_proposal`. Module
  header documents the state machine and safety properties.
- **`src/lib.rs`** — registers the module; adds a `get_admin` view; exposes the
  recovery methods on `TaskManagerContract`.
- **`src/events.rs`** — `emit_recovery_proposed` / `_approved` / `_executed`
  (old→new admin) / `_cancelled`.
- **`src/social_recovery_test.rs`** — 24 unit tests.
- **`README.md`** — module table row + "Social Recovery" feature section.

## Test plan

- [x] `cargo test --lib social_recovery` — **24 passed, 0 failed**, covering:
  - successful 3-of-3 recovery rotates the admin; old admin loses / new admin gains admin powers; proposal ends `Executed` and inactive.
  - custom threshold of 1 (proposer alone → `Approved` → execute).
  - eligibility: sub-Master proposer / approver rejected; `is_recovery_guardian` view for Master, Legend, and below.
  - state machine: threshold-not-met can't execute (status stays `Pending`); double-approve, proposer re-approve, double-execute, execute-while-`Pending` all rejected.
  - TTL: expired proposal can't be approved or executed.
  - role transitions: proposing the current admin rejected; stale execution after the admin moved rejected; execution re-validates the guardian set (a guardian slashed below Master drops the count below threshold → refused).
  - single active proposal enforced; new proposal allowed after cancel; stale active proposal auto-expired by the next `propose_recovery`.
  - cancellation: stranger can't cancel; proposer and sitting admin can.
  - config: admin-only, rejects zero threshold; defaults (3 / 604800) when unset.
- [x] `cargo test --lib` — 140 passed / 12 failed. The 12 failures are
